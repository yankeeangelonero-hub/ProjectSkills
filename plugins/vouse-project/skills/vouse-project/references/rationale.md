# Rationale — the production failures this design answers

This suite is the second-generation redesign of a heavier system (the
original Vouse plugin: versions + slices + Kanban + Actor Flows + Roadmap
FEAT-graph + orchestrator/logger agents + claimed hooks), audited after
three weeks of intensive use on a simulation project. The baseline evidence
below is production behaviour, observed and documented — treat it as this
skill's RED phase. Each failure maps to a design rule.

| Observed failure (production baseline) | Design answer |
|---|---|
| The Kanban board rendered **0 cards** for weeks; nobody noticed because real state lived elsewhere. A state artefact that can rot silently becomes a lying artefact. | State is **derived or deleted**: MAP's table is regenerated by script from frontmatter; there is no hand-maintained board. |
| CLAUDE.md claimed a citation validator "runs as a gate on every artefact write" — **no hook was wired anywhere**. Believed-but-absent enforcement is worse than none. | "Nothing is claimed that isn't wired." LAW rows carry *enforced by*; the guard hook ships with the suite and installs via a settings snippet. |
| The strict roadmap validator failed across two consecutive closes (deferred FEAT registration, date-order errors) and everyone learned to ship past red. | **Scripts assert facts, never taste.** Validators check hashes, enums, file existence — anything needing context routes to judgment. A red gate that stays red gets fixed or removed. |
| The dominant work of the period — measurement campaigns run as batches against a blind reference — ran **outside the slice structure** and was retrofitted at every close. | **Campaign is a first-class work unit** beside slice, with freeze-at-start semantics instead of freeze-at-end. |
| A blind comparison missed on every scored case because one input lineage (a record-to-type assignment) was not pinned in the freeze while every config hash was. | Freeze notes pin **derivation lineages**, not just files — stated as first-order in `record.md`. |
| Two run batches shared a label namespace; a rerun silently overwrote one config's results with another's, and the substitution was invisible in every downstream artefact that read them. | Mechanical namespace/pin checks belong in scripts at the point of writing, and results carry config identity in their own names. |
| The mandated session-start read order was ~300 KB; sessions actually ran on a memory layer + a 5 KB index. | Cold start = MAP + two LEDGER entries, under 10k tokens. Deep corpus is pull-on-demand. |
| Every mirror pair (skill↔docs copy, curated↔runtime presets) drifted or required manual re-sync. | **One fact, one home, one writer** — and skills live tracked in the repo instead of mirrored. |
| A living instruction file accumulated four "owner-authorized exceptions" to its own edit-routing rule in three weeks. | Routing prices factual corrections cheaply (tier 1) and treats repeated exceptions as a signal the document is mis-scoped. |
| A version opened for one scope and closed days later carrying unrelated campaign work, with most of its slices unfinished. | Versions are boundaries for build work only; campaigns open and close on their own clock. |
| Seed test (fresh subagent, empty directory, first release of this suite): the agent produced a correct seed but had to **invent the entire bootstrap** — 10 documented gaps: no init workflow, script install location implied, "version" had no defined representation, deferred future campaigns had no home, git presupposed, hook paths ambiguous. | **Scaffold-then-fill**: `init.py` seeds everything (artefacts, scripts, hooks, git) and `new_unit.py` generates unit files — structure by script, `<FILL:>` slots for the LLM, `check_fill.py` proves completion. A version is declared to be *not a file*; deferred work is declared to live as a MAP milestone row. |

## What was kept, deliberately

The frozen-record discipline (findings, freezes, supersession-only), the
narrative ledger, the close-time "one-off or standing?" grilling, and
slice acceptance rigor — each had repeatedly converted expensive mistakes
into standing protections, and none is replaceable by retrieval tooling or
a changelog alone: a knowledge graph is descriptive; freezes and one-shot
rules are prescriptive.

## Second round of failures, second round of answers

The rows below were added after the artefact model had been in use. They
follow the same rule as the table above: each names an observed failure, not a
hypothesised one.

| Observed failure | Design answer |
|---|---|
| Project knowhow — how to stage a run, which flag combination is correct, which step everyone gets backwards — lived in one person's head and in chat scrollback. A second person joining repeated the same three mistakes, and the first person answered the same three questions. | `skills/` at the project root, tracked in git so it arrives with the clone. Living documents, edited on contradiction, indexed by a generated MAP table. |
| Knowhow that did get written down was written at the moment of frustration and never at the moment of completion, so the expensive lessons of a finished slice evaporated with the session. | The **skills scan** is a `<LATER:>` slot in the slice and campaign templates, posed to the owner at close, and `check_work.py` refuses `done` or `closed` while it is unfilled. The capture point is the close, and it is a gate rather than a prompt. |
| Known defects were tracked in chat, commit messages, and code comments. The same bug was diagnosed three times by three people, and a workaround discovered once was rediscovered twice. | `issues/`, one living file per defect, with the workaround as a first-class section. Unresolved issues surface in MAP; filing is explicitly not scheduling, so filing stays cheap. |
| A defect discovered during a slice was mentioned in the LEDGER prose and never filed, which converted a known issue into an unknown one at the exact moment someone knew it. | Issue reconciliation is a numbered close step beside the skills scan: fixed ones get `fixed_by`, discovered ones get filed, open ones stay visible. |
| Agents working in the repository had no standing instructions and rediscovered the conventions each session, or ignored them. | `CLAUDE.md` is seeded by `init.py` and carries **behaviour only** — MAP carries state. An existing CLAUDE.md is never overwritten; init says so and leaves the merge to a human. |

The skills directory sits at the project root rather than under `.claude/`
deliberately: a visible tracked directory cannot be gitignored by accident,
and the knowhow is legible to someone browsing the repository without any
agent tooling. The cost is that nothing discovers it automatically, which is
why MAP's generated table is stated to be the index and why `regen_map` is
named at every point a skill is created.

## Testing status (honesty section)

- Grounded in documented production baselines (above): the artefact model,
  campaign semantics, derived-state rule, enforcement claims rule.
- **Seed path**: baseline-tested with a fresh subagent on release 1 (10
  gaps found, table above), mechanically re-verified after the
  scaffold-then-fill rework (init → new_unit → check_work → check_fill →
  regen_map chain, positive and negative cases, guard hook liveness).
- **Skills and issues layer**: mechanically verified end to end (init seeds
  `skills/` `issues/` `CLAUDE.md`; `new_skill` / `new_issue` scaffold and
  refuse to overwrite; `check_issue` enums and `fixed_by` / `duplicate_of`
  requirements, positive and negative; `regen_map` renders all three tables;
  `check_work` refuses `done` and `closed` with an unfilled skills-scan slot
  and names the section; the guard hook leaves `skills/` and `issues/`
  editable; a commit shows both directories tracked). **Not** yet tested is
  whether a cold agent under deadline actually poses the scan to the owner
  rather than filling the slot itself — the gate proves the slot is filled,
  never that the question was asked. That is the next subagent scenario to
  run.
- **Not yet pressure-tested with fresh subagents**: the exact wording of the
  close checklist and route triggers against a cold agent under time
  pressure. Before treating the discipline sections as bulletproof, run the
  scenarios in `superpowers:testing-skills-with-subagents` (close-with-
  unfinished-work under deadline; record-edit temptation "just a typo";
  campaign mid-flight config change) and extend the red-flags lists with
  whatever rationalizations surface.
